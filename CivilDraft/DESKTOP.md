# CivilDraft — نسخة سطح المكتب (Windows exe)

## المتطلبات
- Node.js 18 أو أحدث
- Windows 10/11 (يُفضّل بناء exe على ويندوز)

## أول مرة
    npm install

## التشغيل أثناء التطوير
    npm run desktop          # من ملفات المشروع مباشرة (أو dist إن وُجد)
    npm run desktop:build    # يبني dist ثم يشغّل النسخة المصغّرة

## بناء ملف exe
    npm run dist:win         # برنامج تثبيت + نسخة محمولة (x64)
    npm run dist:portable    # نسخة محمولة فقط (x64)
    npm run dist:win:arm     # اختياري: ويندوز arm64 (مثبّت + محمول)

الناتج في مجلد release/:
- CivilDraft-Setup-1.1.0.exe
- CivilDraft-1.1.0-portable.exe
- CivilDraft-Setup-1.1.0-arm64.exe          (dist:win:arm فقط)
- CivilDraft-1.1.0-portable-arm64.exe       (dist:win:arm فقط)

`dist:win:arm` منفصلٌ عمداً: لا يغيّر `dist:win`، وأسماء ملفّاته تحمل `-arm64` فلا تكتب فوق ملفّات x64.
تُمرَّر إليه وسائط electron-builder بعد `--`، مثل: `npm run dist:win:arm -- --publish never`.
يعمل البناء من جهاز x64 (لا يحتاج جهاز ARM)، أمّا تجربة الناتج فتحتاج ويندوز على ARM.

## حجم الملفّات وبصمة SHA256
    npm run release:info             # الملفّات المباشرة في release/: الحجم + SHA256
    npm run release:info -- --all    # يشمل المجلّدات الفرعية أيضاً (win-unpacked كبير)
    npm run release:info -- --sums   # يكتب release/SHA256SUMS.txt (يُتحقَّق بـ sha256sum -c)

مفيد قبل رفع الملفّات إلى GitHub Releases ليتأكّد المنزِّل من سلامة الملف.

## ما الذي يدخل الحزمة
الحزمة (app.asar) = `desktop/` + `dist/` + `build/icon.ico` + `package.json` + اعتماديات الإنتاج (`electron-updater` وما تجرّه) فقط.
- قائمةٌ بيضاء في `files:` داخل electron-builder.yml، ومعها استثناءاتٌ صريحة: `js/tests` و`audit` و`docs` و`*.md` و`*.map`.
- `dist/` يبنيه scripts/build-dist.js (قائمةٌ صريحة أيضاً، ويفشل إن تسرّب إليه tests/audit/docs).
- حارس scripts/after-pack.cjs يفتح app.asar الناتج فعلاً بعد التغليف ويُفشل البناء إن وجد فيه ما ليس من القائمة أو وجد dist بلا index.html. محتوى `node_modules` الخارجي مستثنى من قواعد md/map/docs/tests (هي تحرس ملفّاتنا). يطبع عند النجاح سطراً مثل `after-pack [win-unpacked]: ✓ …`.
- المصدر نفسه (js/ وcss/ وindex.html في جذر المشروع) لا يُحزَم؛ الغلاف يخدم `dist/` فقط.

## الاختبارات
- آلية (Playwright + Electron): `npm install` ثم `npm run test:e2e` (أو `npm run test:e2e:headed` لرؤية النافذة). على لينكس بلا شاشة: `xvfb-run -a npm run test:e2e`.
  تُطلق كلُّ حالةٍ البرنامجَ الحقيقيّ بمجلّد بيانات مؤقّت (`--user-data-dir`) فلا تمسّ بياناتك. الشيفرة في `desktop/e2e/` ولا تدخل الحزمة (مستثناةٌ في electron-builder.yml ويحرسها after-pack).
  - نافذة الفتح الأصلية لا يلمسها Playwright، فتُستبدل في الاختبارات بـ`stubOpenDialog(app, path)` (يعيد مساراً معطى ويسجّل خيارات كل استدعاء)، وتُقرأ الخيارات بـ`openDialogCalls(app)`. أمّا `clickMenu(app, "CmdOrCtrl+O")` فيضغط عنصر القائمة كما تفعل نقرة الفأرة، بلا ضغطة مفتاح. **هذا يغطّي منطق الغلاف والواجهة، لا النافذة الأصلية نفسها**؛ هي في `QA-DESKTOP.md`.
  - على مجلّد بيانات جديد تغطّي شاشةُ الترحيب (`#welcome`) ثم الجولةُ (`#tour`) اللوحة، فلا تصلها النقرات. تغلقهما `settleUi` (في `desktop/e2e/ui.js`) قبل أي رسم. وتُرسَم الجدران عبر سطر الأوامر (`wall` ثم نقطتان ثم Esc) لا بنقرات الفأرة، لأنّ شريط الخيارات `#optbar` يظهر بعد أوّل نقرة ويغطّي نقاطاً من اللوحة في النوافذ الصغيرة. **الرسم بالفأرة نفسه غير مغطّى آلياً** (انظر `QA-DESKTOP.md` §2).
  - `waitStored(page, n)` ينتظر أن يبلغ الحفظ التلقائي عدد الجدران بالضبط قبل الإغلاق أو القتل.
- يدوية: `QA-DESKTOP.md` — ما لا يُختبر آلياً (الحوارات الأصلية، DPI، Excel/AutoCAD، Ollama، بلا إنترنت، ويندوز 10/11).

## كيف يعمل
- desktop/main.cjs: النافذة، بروتوكول app://civildraft/، CSP، القوائم، الحفظ
- desktop/preload.cjs: جسر آمن window.civilDesktop
- desktop/argv.cjs: استخراج مسار ملفّ المشروع من وسائط التشغيل (يُختبَر في Node)
- desktop/updater.cjs: التحديث التلقائي عبر GitHub Releases (قراره ومعالجه يُختبَران في Node بلا Electron)
- js/io/platform.js: طبقة الواجهة التي تكتشف الجسر؛ بدونه تبقى نسخة الويب كما هي
- electron-builder.yml: إعدادات التغليف
- build/icon.ico: أيقونة البرنامج (16–256)
- build/file-icon.ico: أيقونة ملفّات `.cdraft` (16 و32 و48 و256) — تُولَّد بـ`npm run icons:file` (Python + Pillow) من scripts/gen-file-icon.py
- scripts/after-pack.cjs وscripts/dist-win-arm.js وscripts/release-info.js: حارس الحزمة، بناء arm64، وتقرير release/

- البيانات (localStorage/IndexedDB) محفوظة في %APPDATA%/CivilDraft. من قائمة «ملف ⟵ فتح مجلّد البيانات» تصل إليها.
- كل أزرار التنزيل الحالية تفتح نافذة «حفظ باسم» الأصلية تلقائياً.
- عامل الخدمة معطّل في نسخة سطح المكتب فقط (js/app.js)، ونسخة الويب كما هي.
- الأمان: contextIsolation + sandbox + بلا nodeIntegration، والروابط الخارجية تفتح في المتصفّح.

## نقل بيانات نسخة الويب
صدّر نسخة احتياطية من نسخة الويب ثم استوردها في البرنامج.

## التحديث التلقائي والنشر (المرحلة 7)
- يفحص البرنامج عند التشغيل بصمت (بعد ~8 ثوانٍ من ظهور النافذة)، ويسأل المستخدم **قبل التنزيل** ثم **قبل التثبيت**. يدوياً: «مساعدة ⟵ التحقّق من التحديثات…».
- معطَّل في: **النسخة المحمولة** (يُكشَف بمتغيّرات `PORTABLE_EXECUTABLE_*`)، ووضع التطوير، وأي بناءٍ محلّيّ بلا `app-update.yml`، و`CIVILDRAFT_NO_UPDATE=1`.
- البناء المحلّي (`npm run dist:win`) لا يحتاج مستودعاً ولا رمزاً: إعداد `publish` يمرّره `.github/workflows/release.yml` وحده، فالبناء المحلّي يبقى بلا تحديث تلقائي.
- الإصدار: ادفع وسماً `v*` يطابق `version` في package.json ⟵ يبني release.yml على `windows-latest` ويرفع الملفّات إلى Release **مسوّدةً**.
- التوقيع الرقمي اختياري عبر أسرار GitHub `CSC_LINK` و`CSC_KEY_PASSWORD`؛ بلا الأسرار يُبنى exe غير موقَّع.
- التفاصيل الكاملة (الخطوات، SmartScreen، التراجع عن إصدار): **RELEASE.md**.
- الاختبارات: `npm run test:updater` و`npm run test:release`.

## ملاحظات
- بدون توقيع رقمي يظهر تحذير SmartScreen أول مرة («مزيد من المعلومات ⟵ تشغيل على أي حال»). انظر RELEASE.md.

## القائمة والاختصارات (المرحلة 3)
| الأمر | الاختصار | ما يفعله |
|---|---|---|
| مشروع جديد | Ctrl+N | ينقر زرّ «مشروع جديد» نفسه (بتأكيده) |
| فتح ملفّ المشروع | Ctrl+O | يفتح نافذة اختيار الملفّ الأصلية (`dialog.showOpenDialog`)، ويمرّ الملفّ المختار إلى `openText` نفسها التي يستعملها زرّ «افتح» |
| حفظ المشروع | Ctrl+S | ينقر «احفظ المشروع» نفسه |

«جديد» و«حفظ» تنقران الأزرار الموجودة. «فتح» يختلف في أوّله فقط: لا ينقر زرّ «افتح» (الذي يُنشئ `<input type=file>`)، بل يستدعي `civilDesktop.openFile` ← `dialog.showOpenDialog` في الغلاف. والسبب أنّ Chromium يحجب نافذة `<input type=file>` ما لم تسبقها إيماءةُ مستخدمٍ داخل الصفحة، والنقر بالفأرة على قائمة الغلاف الأصلية ليس إيماءةً في الصفحة، فكان «فتح» من القائمة يفشل بصمت. نافذة النظام لا تحتاج إيماءة. بعد الاختيار يمرّ النصّ إلى `openText` نفسها، فتبقى الفحوص والتأكيدات والتقارير واحدة. مرشّح النافذة يُشتقّ من `PROJECT_ACCEPT` في `js/io/project.js` (`cdraft` و`json` و`mistar`، ثم «كل الملفات»). إن غاب الجسر أو رمى الاستدعاءُ استُعيد النقرُ القديم على الزرّ؛ وفي هذه الحالة قد يعود الحجب نفسه، فهو احتياطٌ لا مسارٌ موثوق.
قراءة الملفّ في الغلاف محدودة بحدّ الحجم نفسه (`MAX_OPEN_BYTES`)؛ ما تجاوزه يُبلَّغ بخطأ.

## الامتداد .cdraft وفتح الملفّات بالنقر المزدوج
- نسخة سطح المكتب تحفظ المشروع باسم `الاسم.cdraft` (المحتوى JSON نفسه). نسخة الويب تبقى `.json`.
- يُفتح من البرنامج: `.cdraft` و`.json` و`.mistar` (القديم).
- أيقونة ملفّ `.cdraft` في المستكشف هي build/file-icon.ico (ورقةٌ بزاويةٍ مطويّة وشعار البرنامج)، لا أيقونة البرنامج نفسها. تُنسَخ مع المثبّت إلى مجلّد التثبيت؛ إن لم تتغيّر على جهازٍ جُرّب عليه إصدارٌ سابق فأعِد تشغيل المستكشف أو امسح كاش الأيقونات.
- ربط النقر المزدوج بـ`.cdraft` يُسجَّل مع **برنامج التثبيت فقط**. النسخة المحمولة لا تُسجَّل في ويندوز؛ شغّلها ثم افتح الملفّ من داخلها.
- إن كان البرنامج يعمل ونقرتَ على ملفّ آخر، يُفتح في النافذة نفسها (نسخةٌ واحدة).
- لا يُربَط `.json` بالبرنامج عمداً: امتدادٌ أوسع من أن يُستولى عليه.

## النسخة الاحتياطية الخارجية
تستعمل File System Access API. يمنح الغلاف إذن `fileSystem` لواجهة البرنامج وحدها. الإذن لا يبقى بين التشغيلات، فيطلب البرنامج تفعيل الزرّ من جديد في كل جلسة.

## نافذة الترحيب
تظهر مرّةً واحدة عند أول تشغيل، وتشرح نقل المشروع من نسخة الويب. تُعاد من «ملف ◂ نقل بيانات من نسخة الويب». علامة أول تشغيل: `first-run.json` في مجلّد البيانات (احذفه لتظهر ثانيةً).

## اتجاه القوائم
اتجاه شريط القوائم الأصلي يتبع لغة ويندوز لا لغة التطبيق. للتجربة: `set CIVILDRAFT_RTL=1` قبل `npm run desktop`.
